# Local model runtime candidates

## Status

This is a Phase 2.6 research note, not a runtime selection. The application still uses the null/unavailable local adapter. No WebLLM or Transformers.js dependency is installed, no model URL is approved, and no model has been downloaded or benchmarked.

The platform decision is intentionally provider-neutral. A candidate becomes eligible for production only after the license, artifact integrity, device-tier fit, benchmark evidence, privacy review, and operational controls in the benchmark plan are complete.

## Cross-cutting requirements

1. **Capability is not readiness.** `AICapabilityReport` describes device/browser evidence. `ModelArtifactManifest` and `ModelReadinessState` describe an approved, intact, installed artifact. `LocalRuntimeAdapter` describes runtime state. The UI/service must not collapse these into one “AI ready” boolean.
2. **No remote-by-default production path.** A selected artifact must be pinned to a project-controlled host/CDN, include a checksum/integrity record, and require an explicit user action before download. Mutable model IDs, unreviewed Hub URLs and runtime CDN imports are not approval evidence.
3. **Offline is a state, not a promise.** Offline inference can be claimed only after runtime binary and all model files are present and verified locally. A cached partial download is `needs-model`/`unavailable`, not ready.
4. **No benchmark, no promotion.** Candidate without real latency, memory, quality, language/task coverage and license evidence stays `candidate`, `benchmarkStatus: not-run` or `needs-evidence`, and `productionReady: false`.
5. **Language-platform scope.** Benchmark tasks are generic platform capabilities (conversation, explain, feedback, generate-practice, summarize, classify, assess, plan-study and recommend-next-practice). Exam-pack terminology does not belong in this provider decision.
